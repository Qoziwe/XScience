# XScience — правила работы (anchored-first)

Проект: хакатон-прототип панели оценки пожарной обстановки на космическом корабле
в условиях микрогравитации. Фронтенд переписан на React (`frontend/`, см.
`frontend/README.md`) по мотивам исходного HTML/CSS/JS-прототипа
(`XScience Login.dc.html`, `XScience Console.dc.html` — остаются как
референс дизайна, не редактируются). Бэкенд (Flask) реализован в `backend/`
(см. `backend/README.md`); исходный план — `BACKEND.md`.
Полный разбор правил расчёта — см. README.md и FUNCTIONAL_SPEC.md, но для
работы в сессии не перечитывать их напрямую — см. правило ниже.

## Правило: всё через anchored

Для максимальной экономии токенов в этом проекте все операции с памятью,
поиском контекста и чтением крупных файлов обязаны идти через MCP-сервер
`anchored`, а не через нативные инструменты:

1. **Начало сессии** — первым делом вызвать `anchored_context(cwd=...)`.
   Не начинать работу и не отвечать, пока контекст не подгружен.
2. **Поиск фактов/решений/истории проекта** — `anchored_search` /
   `anchored_kg_query`. Не грепать и не перечитывать файлы заново, если
   ответ может быть в памяти.
3. **Изучение документации и больших файлов** (README.md, FUNCTIONAL_SPEC.md,
   support.js, *.dc.html, industry.css) — сначала `anchored_index`, затем
   все вопросы по содержимому — через `anchored_ctx_search`, а не через
   прямой `Read`/`cat`.
4. **Запуск команд с объёмным выводом** (сборка, тесты, grep по большим файлам,
   git-история) — `anchored_execute` / `anchored_batch_execute` вместо
   голого Bash, если вывод большой.
5. **Обработка файла без цели его редактировать** — `anchored_execute_file`
   вместо `Read`.
6. **Новые факты, решения, причины багов** — сохранять немедленно через
   `anchored_save` (fact/decision/learning/plan/event — по смыслу), не
   держать только в контексте диалога.
7. **Исключение**: `Read`/`Edit`/`Write` используются как обычно для файлов,
   которые реально редактируются в текущей задаче — anchored не подменяет
   точечное редактирование кода.

Эти правила — проектное решение пользователя, зафиксированное также в
anchored-памяти (категория preference, scope=project).
